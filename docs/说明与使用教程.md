## 一、这个脚本做什么

把英文网页的段落翻译成中文，**插在原文的上方或下方**，形成双语对照：原文保留、页面结构不改、代码块不动。它和「整页机翻」的区别是——你能随时对照原文看术语、命令、函数名。

四个核心能力：

| 能力 | 说明 |
|---|---|
| **双语对照** | 译文以独立行插入英文段落上方或下方，带浅色底和「译」标记，点一下译文可淡化，方便看原文 |
| **自动识别网页** | 自己判断页面语言、站点类型、GitHub 页面类型，决定要不要翻、按什么策略翻；中文网站默认不打扰 |
| **GitHub 专项** | 跳过代码页、diff、文件名、编辑器；内联代码（如 `npm install`）原样保留；GitHub 无刷新跳转自动重翻 |
| **多翻译源** | 有道（默认、开箱即用）/ 百度翻译开放平台 / 本地离线服务 / 本地大模型（Ollama、OpenAI 兼容接口） |
| **滚动持续补翻** | 边滚边补扫漏掉的段落：懒加载观察器漏触发、折叠内容展开、长页面超出单轮 300 段上限、Cloudflare 验证页/骨架屏后正文才出现，都会自动补上 |
| **限流自动恢复** | 有道 411 触发 30 秒冷却时会显示倒计时，冷却结束自动补翻，无需刷新；失败的段落会退避重试，不会永久空白 |

默认面向「GitHub + 纯英文外网」，不需要配黑白名单，装上就能用。

## 二、安装（3 分钟）

1. 浏览器安装用户脚本管理器，推荐 **Tampermonkey**（Chrome / Edge / Firefox / Safari 均有）。
2. 打开扩展的「添加新脚本」，把 `github网页英译中双语对照.user.js` **拖进浏览器窗口**；或新建脚本后把文件内容全选粘贴进去，按 `Ctrl/Cmd + S` 保存。
3. 首次访问英文页面时，Tampermonkey 会弹 **跨域访问授权**（`@connect`），点「始终允许」或「允许全部域名」。脚本要向翻译接口发请求，不授权就不会有译文。
4. 打开任意 GitHub 仓库 README、Issue 或英文文档页，左下角出现半透明毛玻璃质感的圆形「**译**」按钮（静置时淡淡地透出页面内容，鼠标移上去会变清晰），等 1～3 秒即出现译文。想让图标回到右下角，在「译」→「图标位置」里点「右下角」。

> 想翻译本地 `file://` 打开的 HTML：在 Chrome 扩展管理页给 Tampermonkey 打开「允许访问文件网址」。

覆盖安装旧版本不会丢配置，新增选项自动取默认值。

### 方案 B：不装油猴，用 Chrome 扩展

如果你不想装 Tampermonkey，仓库里提供了功能完全相同的 Chrome 扩展（Manifest V3），主脚本原样复用：

1. 下载扩展包：到 https://github.com/ljp801005-tech/github-en2zh-bilingual/releases/latest 下载 `github-en2zh-bilingual-chrome-v*.zip`；或在仓库页面直接取 `chrome-extension/` 目录。
2. 解压 zip 到一个固定位置（别放在「下载」里随手清理，扩展会一直引用这个目录）。
3. 打开 Chrome 地址栏输入 `chrome://extensions`，右上角打开「**开发者模式**」。
4. 点「**加载已解压的扩展程序**」，选中刚解压出来的文件夹（里面能看到 `manifest.json`）。
5. 打开任意英文网页，左下角出现「译」按钮就成功了；**已经打开的标签页需要刷新一次**。
6. 要翻译本地 `file://` 网页：在扩展卡片上点「详情」→ 打开「允许访问文件网址」。
7. 点浏览器工具栏上的扩展图标，可以查看当前翻译源、译文位置、启用状态和快捷键。

扩展的「译」按钮、设置面板、快捷键、识别规则与油猴版完全一致。区别只有两点：配置存在浏览器的扩展存储里（与油猴版的配置**互不共享**，首次使用选一次翻译源即可），以及升级扩展需要重新下载并替换目录。

> 从源码安装（开发者）：把 `chrome-extension/` 目录直接作为「已解压的扩展程序」加载即可，目录里的 `content/userscript.js` 由 `scripts/build-extension.sh` 从主脚本同步生成。

## 三、界面与快捷键

点左下角「译」展开设置面板，**面板顶部会实时显示自动识别结果**（站点类型、页面类型、中文占比、是否运行及原因）。按钮旁的角标显示「已译 N 段 · 队列 N · 失败 N」。

1.4.0 起图标默认在**左下角**，避免挡住网页右下角的「回到顶部」、客服、悬浮菜单等常用按钮；设置面板里「图标位置」可在「左下角 / 右下角」之间切换，选择会保存，老版本升级后自动取左下角。

1.5.0 起图标换成**半透明毛玻璃**：渐变蓝底 + 背景模糊 + 顶部柔光 + 细白边，静置时约 70% 不透明度、能透出底下的网页，鼠标悬停或打开设置面板时平滑变清晰并轻轻上浮，按 `Alt + T` 暂停翻译后变成灰色玻璃态。设置面板同样是半透明玻璃卡片、带淡入动效，深色模式有独立配色；系统开启「减少动态效果」时会自动关掉动画。图标大小、位置和所有快捷键都没变。

| 快捷键 | 作用 |
|---|---|
| `Alt + T` | 开启 / 暂停翻译（不卸载脚本） |
| `Alt + P` | 译文在英文上方 ⇄ 下方，一键切换 |
| `Alt + Enter` | 立即翻译本页；**可强制翻译被自动识别跳过的页面** |
| `Alt + S` | 划词翻译（需先在设置里打开「划词翻译」），译文气泡显示 6 秒 |

Tampermonkey 图标的右键菜单里还有：开启/暂停、上/下切换、立即翻译本页、清除本页译文、重新识别本网页、打开设置面板。

设置面板底部四个按钮：`立即翻译本页`、`测试翻译源`、`清除本页译文`、`清空缓存`。

## 四、常用场景速查

| 想做什么 | 怎么做 |
|---|---|
| 译文改到英文上方 | `Alt + P`，或设置里「译文位置」选「上方」 |
| 图标看着太淡 | 1.5.0 起默认半透明，鼠标移上去会自动变清晰；点击区域和快捷键不变 |
| 图标挡住网页元素 | 设置里「图标位置」切换到另一角（左下 ⇄ 右下） |
| 某个英文站没自动翻 | 先看面板顶部的「跳过原因」；直接按 `Alt + Enter` 强制翻；或把「运行范围」改成「所有网站」 |
| 中文网站被误翻 | 默认不会；若发生过，把「中文占比阈值」调小（如 1） |
| 页面太吵 / 只想手动翻 | 关掉「自动翻译」，之后用 `Alt + Enter` 按需翻译 |
| 永久不翻某个网站 | 设置里点「加入黑名单 / 移出」 |
| 翻译太慢 | 有道演示接口限速 1.4 秒/批；改用本地离线服务（0.12 秒/批）或百度开放平台（0.4 秒/批） |
| 往下滑就不翻译了 | 升级到 1.3.0；滚动会自动补扫。若状态显示「限流中 Ns」，等倒计时结束会自动继续；按 `Alt + Enter` 可立即补一次 |
| 译文错位或重复 | 点「清除本页译文」，再 `Alt + Enter` |
| 清空所有历史译文 | 点「清空缓存」 |

## 五、自动识别网页（重点）

判定顺序如下，任一环节判定跳过就不会翻译：

1. **站点黑名单**：命中直接跳过，优先级最高。
2. **运行范围**（设置项，默认「自动」）：
   - `自动`：命中站点白名单 → 运行（**GitHub 系豁免中文检测**，Issue 里混中文评论也照译英文部分）；否则正文中文字符占比 > 阈值（默认 **2%**）→ 判定中文页并跳过；否则按纯英文页运行。
   - `仅白名单站点`：只跑白名单，其它一律不翻。
   - `所有网站`：不看语言和站点，全部运行。
3. **语言依据**：`html[lang]` → `meta[http-equiv=content-language]` → 正文前 30000 字的中文字符占比。统计时会**扣除脚本自己注入的设置面板和译文**，避免把英文页误判成中文页。
4. **站点/页面类型识别**：GitHub / GitHub Pages / GitHub Raw / 问答社区（Stack Overflow、Stack Exchange）/ 技术文档（MDN、Python Docs、docs.github.com）/ 普通网站；GitHub 内部再分代码页、Issue、Pull Request、Discussion、Wiki、仓库页。
5. **段落级过滤**：短于 20 字符、英文单词少于 4 个、含中文字符、纯 URL/邮箱、像代码的文本，以及输入框、代码块、编辑器、徽标、导航、页脚，都不翻译。

默认白名单：`github.com`、`gist.github.com`、`docs.github.com`、`github.io`、`raw.githubusercontent.com`，可在「白名单域名」里用逗号增删（支持子域名匹配）。

**关闭自动识别**：把「自动识别网页」取消勾选，脚本就回到全局规则，只按「自动翻译 / 黑名单 / 运行范围」工作。

## 六、翻译源

| 源 | 需要配置 | 请求间隔 | 特点 |
|---|---|---|---|
| **有道（默认）** | 无 | 1.4 秒/批 | 网易有道 AI 官方演示接口，国内直连、免注册、译文质量最好；有频率风控（错误码 411），脚本自动退避重试 |
| **百度开放平台** | appid + 密钥 | 0.4 秒/批 | 到 [fanyi-api.baidu.com](https://fanyi-api.baidu.com/) 免费申请，最稳定、无限流，签名已内置 |
| **本地离线服务** | 接口地址 | 0.12 秒/批 | 完全不出本机，见下一节；译文质量略弱于有道 |
| **本地大模型** | 协议 + 地址 + 模型名 | 0.12 秒/批 | 协议选 `ollama` 或 `openai`，接本机 Ollama / LM Studio 等，质量可超过在线接口 |

「失败自动回退」默认开启：主源失败时依次尝试本地服务 → 百度（填了密钥才用）→ 有道。切换翻译源后建议点一次「测试翻译源」，会用固定样例句验证连通性。

多行文本会合并成一批请求（换行分隔），译文行数必须与原文严格一致，否则自动降级为逐条翻译。

## 七、本地离线服务（可选，已在本机装好）

服务端位于 `local-translator/`，用 CTranslate2 + OPUS-MT 英中 int8 量化模型（约 76MB），纯 CPU、完全离线、不需要 Docker 或 PyTorch，接口兼容 LibreTranslate 协议并开放 CORS。

**启动（macOS）**：双击 `local-translator/启动本地翻译.command`，看到启动提示后**保持终端窗口开着**，关闭窗口即停止服务。

**自测**：

```bash
curl -s http://127.0.0.1:8787/health
curl -s -X POST http://127.0.0.1:8787/translate \
  -H 'Content-Type: application/json' \
  -d '{"q":"Hello world","source":"en","target":"zh"}'
```

**在脚本里启用**：左下角「译」→ 翻译源选「本地离线服务」→ 接口协议选 `LibreTranslate` → 地址填 `http://127.0.0.1:8787/translate` → 点「测试翻译源」。

**换一台机器部署**（Python 3.9+，首次需联网下载模型）：

```bash
cd local-translator
bash setup.sh                              # 建虚拟环境、装依赖、下载模型，只需一次
.venv/bin/python server.py --port 8787     # 或仍用 .command 双击启动
```

端口被占用时改 `--port`，并同步修改脚本设置里的接口地址。请求由 `GM_xmlhttpRequest` 从扩展后台发出，在 https 页面上访问 `http://127.0.0.1` 也不会被页面混合内容策略拦截。

## 八、GitHub 上的具体表现

**会翻**：README 渲染区（`.markdown-body`）、Issue / PR / Discussion 的正文与评论、Wiki、文档站正文、`article` / `main` 等正文容器。

**不翻**：代码页 `blob-code`、diff 行、`highlight` 代码块、Monaco / CodeMirror 编辑器、文件名、徽标、导航栏与页脚。

**内联代码保真**：`Run npm install to install dependencies` → `运行 npm install 安装依赖项`。脚本先把内联代码、@用户名、commit hash 换成占位符再送翻译，译后按标记还原；本地小模型即使把标记写错，也能按数字锚点容错还原。

**无刷新跳转**：监听 `turbo:load` / `pjax:end` / `popstate` 并轮询 URL，从 Issue 跳到 PR 时自动清除旧译文、重新识别、重新翻译。

## 九、常见问题

**Q：完全没反应？**
① 确认脚本已启用；② 看左下角面板顶部的识别结论与跳过原因；③ 按 `Alt + Enter` 强制翻译一次；④ 确认首次的 `@connect` 授权已允许；⑤ 按 F12 看 Console 是否报错。

**Q：不想安装 Tampermonkey，能用吗？**
能。仓库另提供同一套代码的 Chrome 扩展，见「二、安装 → 方案 B」：下载 zip → 解压到固定目录 → `chrome://extensions` 打开「开发者模式」→「加载已解压的扩展程序」。图标、设置面板、快捷键、识别规则与脚本版完全一致；只是配置和译文缓存各自独立，首次用扩展时选一次翻译源即可。

**Q：状态里出现「411 / 限流中 Ns 后自动继续」？**
有道演示接口的频率风控。脚本会退避重试，连续失败暂停 30 秒，状态栏会显示倒计时；**冷却结束后自动补翻限流期间滚动过的内容，不用刷新页面**。急需可切本地离线服务或百度开放平台。

**Q：为什么往下滑的时候就不自动翻译了？**
1.2.0 及更早版本有四个叠加原因：① 有道 411 触发 30 秒冷却时队列停摆，且冷却结束后不会回头补翻；② 失败的段落被直接作废，不再重试；③ 懒加载的 IntersectionObserver 偶发不回调，已排队段落卡住；④ 单页最多处理 300 段，长页面靠后的段落从未进入队列，折叠/隐藏内容初次扫描被跳过。1.3.0 已全部修复：滚动补扫、失败退避重试、冷却自动续翻、验证页/骨架屏自动重判。设置里可关掉「滚动时补翻遗漏段落」。

**Q：Cloudflare「请稍候… / 正在进行安全验证」的页面不翻译？**
这类验证页的中文占位文字会让脚本误判为中文站。1.3.0 会识别验证页与空白骨架屏，暂缓判定，正文渲染后自动重判并开始翻译。

**Q：中文网站不翻译，是不是坏了？**
设计如此。按 `Alt + Enter` 可强制翻译本页，或把运行范围改成「所有网站」。

**Q：有些英文段落没翻？**
段落级过滤在起作用（太短、含中文、像代码、在导航/代码块里）。可把「最短段落」从 20 调小，或关掉「只翻正文区域」。

**Q：本地源报「网络请求失败」？**
服务没启动、端口不对或地址写错。先跑 `/health` 自测，再点「测试翻译源」。

**Q：划词翻译没反应？**
设置里打开「划词翻译」，选中一段英文后按 `Alt + S`。

**Q：动态加载的内容（无限滚动、评论展开）没翻？**
脚本用 MutationObserver 累积新增节点并防抖扫描，通常 0.7 秒内补翻；若页面框架特殊，按 `Alt + Enter` 手动补一次。

## 十、隐私与权限说明

- `@match *://*/*` 与 `file:///*`：脚本在所有页面加载，是因为「纯英文外网」本身没有固定域名清单；但**默认只在白名单站点或判定为纯英文的页面上真正工作**，可在设置里收紧为「仅白名单站点」。
- `@connect`：声明了 `aidemo.youdao.com`、`fanyi-api.baidu.com`、`localhost`、`127.0.0.1` 以及 `*`。`*` 是为了允许你填写任意本机 / 局域网翻译服务地址；脚本**只会向当前所选翻译源的地址发请求**，不会把页面内容发往其它域名。
- **在线源**会把需要翻译的英文文本发送给网易有道或百度；**本地离线源 / 本地大模型**数据完全不出本机。
- 译文缓存用 `GM_setValue` 存在浏览器本地，最多 2000 条，跨页面复用；可在设置里一键清空。
- 无统计上报、无埋点、无账号体系、不注入任何外部 JavaScript。脚本代码为明文可读，MD5 签名实现依据 RFC 1321 自行编写。
- **Chrome 扩展版**在安装时申请三项权限：`storage`（保存设置与译文缓存）、`scripting`（把主脚本注入页面）、`<all_urls>` 主机权限（等价于脚本里的 `@connect *`，用于访问你所选的翻译服务与任意网页）。跨域请求由扩展后台发出，网页自身的脚本拿不到这些请求内容；扩展同样无统计上报。

## 十二、源码与自动更新

源码仓库：https://github.com/ljp801005-tech/github-en2zh-bilingual ｜ 脚本页：https://greasyfork.org/zh-CN/scripts/604516 ｜ 扩展下载：https://github.com/ljp801005-tech/github-en2zh-bilingual/releases/latest

**GitHub 是唯一代码源，Greasy Fork 只是分发渠道**。同步配置已完成并实测：脚本同步与页面说明同步均指向仓库 raw 地址，仓库 Webhook 已启用（含 GF 生成的密钥），1.4.0 由一次真实同步生成 `Imported from URL` 版本；后续 push 实测返回 200 且页面说明自动更新。维护者改完脚本并提升 `@version` 后 push 到 `main`：

```
push → GitHub Actions 校验（语法 / 元数据 / 版本递增 / 扩展一致性）
     → GitHub Webhook 通知 Greasy Fork
     → Greasy Fork 从仓库 raw 地址拉取，生成新版本（约数十秒）
     → 你的 Tampermonkey 检查到更新
     → （同时）扩展 zip 由 release.sh 挂到 GitHub Release
```

兜底：Greasy Fork 的「源代码同步」设为「自动 - 定期检查更新并同步」，即使 Webhook 没触发也会定期拉取。

| 你的安装方式 | 更新从哪来 |
|---|---|
| 从 Greasy Fork 安装 | 上面的自动同步链路 |
| 直接装 GitHub raw 地址 | Tampermonkey 记住安装 URL，直接检查仓库 raw 文件 |
| 用 Chrome 扩展安装 | 到 Releases 下载新 zip，替换原目录后在 `chrome://extensions` 点「重新加载」；已打开的标签页刷新一次 |

用户侧无需任何操作，Tampermonkey 里点「检查脚本更新」可立即拉取。想提交问题或改进，到仓库 Issues 反馈。
